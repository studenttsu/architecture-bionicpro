# Access Control Policy — Reports API

## Ограничение доступа к эндпоинту отчётности

### Принцип
Пользователь может получить отчёт **только о своём** протезе (или протезах).  
Доступ к данным других пользователей **запрещён**.

### Реализация

1. **JWT-аутентификация** (`auth.py`):
   - Каждый запрос к `GET /reports` должен содержать валидный JWT access token в заголовке `Authorization: Bearer <token>`.
   - Токен валидируется через JWKS-эндпоинт Keycloak (проверка подписи RS256, issuer, audience).
   - Если токен невалиден или отсутствует — возвращается `401 Unauthorized`.

2. **Идентификация пользователя**:
   - `user_id` извлекается из claim `sub` JWT-токена.
   - **user_id НЕ передаётся как параметр запроса** — это исключает подмену идентификатора.

3. **Фильтрация данных** (`main.py`):
   - SQL-запрос к ClickHouse витрине `report_mart` содержит `WHERE user_id = %(user_id)s`, где `user_id` — значение из JWT `sub`.
   - Пользователь физически не может запросить данные другого пользователя.

4. **Ограничение по периоду**:
   - Отчёт генерируется только за период, уже обработанный Airflow ETL.
   - Проверяется `etl_metadata.last_processed_date` — если `date_to` выходит за пределы обработанных данных, он автоматически обрезается.

### Роли (RBAC через Keycloak)
- `prothetic_user` — пользователь протеза, имеет доступ к своим отчётам.
- `administrator` — администратор системы.
- `user` — обычный пользователь (без доступа к отчётам протезов).
